## 4. Шаги воспроизведения

1. Открыть терминал в корне проекта.
2. Запустить программу: `python src/app.py`
3. Дождаться появления главного меню.
4. Ввести команду `add` и нажать Enter.
5. При запросе «Enter title:» нажать Enter, не вводя ни одного символа.
6. При запросе «Enter description:» ввести текст «Тестовое описание» и нажать Enter.
7. Нажать Enter для подтверждения создания задачи.

**Фактический результат:**  
После шага 7 программа выводит сообщение об ошибке `ValueError: empty title not allowed` и аварийно завершается. Управление возвращается в системную командную строку. Никакого сообщения для пользователя не выводится.

- Интерфейс меню работает корректно (команда `add` распознаётся).

### Предполагаемый модуль / файл
- `src/app.py` - основной файл с циклом обработки команд.

### Предполагаемый участок кода

>if not title:

## Задание для закрепления: Почему нельзя исправлять дефект без локализации
Если разработчик начнёт исправлять дефект, не проведя предварительной локализации, он рискует действовать вслепую. Вместо того чтобы устранить коренную причину, он может замаскировать симптом или внести изменения в совершенно не связанный участок кода. Это приводит к пустой трате времени, поскольку после такой "правки" дефект может остаться, а иногда даже породить новые ошибки. Кроме того, без чёткого понимания, где именно и при каких условиях возникает проблема, невозможно ни доказать, что исправление действительно сработало, ни выполнить надёжный ретест. Локализация же позволяет сосредоточить усилия на конкретном модуле или функции, сокращая риск регрессии и делая процесс исправления предсказуемым и проверяемым.
