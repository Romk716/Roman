# Мини-отчёт о тестировании сборки

## 1. Сведения о проверяемой сборке
- **Проект:** Учебный модуль «Сервис задач» (Task Manager).
- **Дата проверки:** 14 апреля 2026 г.
- **Ветка Git:** `main`.
- **Проверяемый коммит:** с изменениями по результатам ЛР 1-7.
- **Окружение:** Python 3.12, Windows 11 Pro, терминал VS Code.

## 2. Объём проверки

Проверка выполнена по чек-листу docs/functional_checklist.md (пункты CL-01 … CL-12) и тест-кейсам docs/test_cases.md (TC-01 … TC-10). Были проверены:

- запуск программы;
- создание задачи с корректными данными;
- просмотр списка задач;
- изменение статуса на допустимый (new -> in_progress -> done);
- изменение статуса на недопустимый;
- поиск по ключевому слову;
- сохранение задач в JSON;
- загрузка задач после перезапуска;
- обработка пустого названия задачи;
- обработка повреждённого JSON;
- поведение при отсутствии файла данных.

## Найденные дефекты

- **#15** - Ошибка программы при пустом названии задачи.
- **#16** - Поиск регистрозависим (должен быть без учёта регистра).
- **#17** - Недопустимый статус принимается как корректный.
- **#18** - Повреждённый JSON вызывает аварийное завершение при запуске.
- **#19** - После перезапуска теряется поле описания задачи.

Все дефекты оформлены в GitHub Issues.

---

## Блокирующие дефекты

Следующие дефекты делают сборку **непригодной к выпуску**:

1. **#18** - Аварийное завершение при повреждённом JSON.  
   Программа не может безопасно запуститься, если файл данных испорчен. Это критично, так как пользователь может потерять данные или не иметь возможности восстановить работу.

2. **#19** - Потеря описания после перезапуска.  
   Нарушает сохранность пользовательских данных. Без исправления модуль нельзя считать надёжным.

3. **#15** - Ошибка при пустом названии.  
   Блокирует базовый сценарий создания задачи, требует перезапуска программы.

Остальные дефекты (#16, #17) являются серьёзными, но не блокируют выпуск, так как основные сценарии (создание, просмотр, сохранение) работают, а несоответствия можно временно объяснить пользователю.

---

## Итоговый статус сборки

**Сборка НЕ ГОТОВА к выпуску.**  
Причина: наличие трёх блокирующих дефектов (#18, #19, #15), которые приводят к потере данных и аварийному завершению программы. Без их исправления демонстрация или сдача проекта невозможны.

## Если бы сборку нужно было показать сегодня

Сегодня сборку показывать нельзя, потому что при пустом названии задачи программа падает, а при повреждённом JSON - аварийно завершается. Эти проблемы видны сразу и испортят впечатление. Если бы всё же пришлось демонстрировать, я бы предупредил: «Не вводите пустое название и не повреждайте файл tasks.json, иначе программа упадёт». В первую очередь перед следующей демонстрацией я бы исправил падение при пустом названии - это самый частый ошибочный сценарий пользователя.
