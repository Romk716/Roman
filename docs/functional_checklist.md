## Чек-лист

### CL-01: Запуск программы
- **Требование:** R-00 (если есть общее требование к запуску) или просто «общее»
- **Сценарий:** S-01 (если применимо)
- **Ожидаемый результат:** Программа запускается без ошибок, выводится приглашение.
- **Важность:** BLOCK

### CL-02: Создание задачи с корректными данными
- **Требование:** R-01
- **Сценарий:** S-01
- **Ожидаемый результат:** Задача создаётся, появляется в списке с уникальным ID.
- **Важность:** BLOCK

### CL-03: Просмотр списка задач
- **Требование:** R-02
- **Сценарий:** S-02
- **Ожидаемый результат:** Список содержит все созданные задачи.
- **Важность:** BLOCK

### CL-04: Изменение статуса задачи на допустимый
- **Требование:** R-03
- **Сценарий:** S-03
- **Ожидаемый результат:** Статус меняется и отображается в списке.
- **Важность:** BLOCK

### CL-05: Сохранение в JSON и загрузка после перезапуска
- **Требование:** R-05, R-06
- **Сценарий:** S-05
- **Ожидаемый результат:** После перезапуска все задачи восстанавливаются.
- **Важность:** BLOCK

### CL-06: Поиск по ключевому слову
- **Требование:** R-04
- **Сценарий:** S-04
- **Ожидаемый результат:** Находит задачу по слову в названии/описании (регистронезависимо).
- **Важность:** WARN

### CL-07: Фильтрация по статусу
- **Требование:** R-11
- **Сценарий:** S-10
- **Ожидаемый результат:** Возвращаются только задачи с указанным статусом.
- **Важность:** WARN

### CL-08: Обработка отсутствия файла данных
- **Требование:** R-07
- **Сценарий:** S-06
- **Ожидаемый результат:** При отсутствии файла модуль работает с пустым списком и создаёт файл при первом сохранении.
- **Важность:** BLOCK

### CL-09: Обработка повреждённого JSON
- **Требование:** R-08
- **Сценарий:** S-07
- **Ожидаемый результат:** При повреждённом файле модуль запускается с пустым списком и перезаписывает файл при сохранении.
- **Важность:** BLOCK

### CL-10: Попытка создать задачу с пустым названием
- **Требование:** R-09
- **Сценарий:** S-08
- **Ожидаемый результат:** Ошибка, задача не создаётся.
- **Важность:** BLOCK

### CL-11: Попытка установить недопустимый статус
- **Требование:** R-10
- **Сценарий:** S-09
- **Ожидаемый результат:** Ошибка, статус не меняется.
- **Важность:** WARN

### CL-12: Уникальность идентификаторов
- **Требование:** R-12
- **Сценарий:** S-01 (при создании двух задач)
- **Ожидаемый результат:** ID созданных задач различаются.
- **Важность:** BLOCK

## Данные для проверки

### Корректные данные
- Задача 1: название «Купить молоко», описание «1 литр»
- Задача 2: название «Сдать отчёт», описание «Подготовить презентацию»
- Задача 3: название «Позвонить маме», описание «Вечером» (для поиска)

### Ошибочные данные
- Пустое название: `""` (пустая строка)
- Недопустимый статус: «отложено» (не входит в список допустимых)
- Повреждённый JSON: файл `tasks.json` с содержимым `{`

## Риск-анализ двух BLOCK-пунктов

### CL-05: Сохранение и загрузка после перезапуска
**Ожидаемый дефект:** Чаще всего можно встретить ситуацию, когда данные не сохраняются при аварийном завершении программы (например, если не вызван явно метод сохранения). Это опасно, потому что пользователь может потерять все свои задачи, что делает модуль бесполезным.

### CL-10: Попытка создать задачу с пустым названием
**Ожидаемый дефект:** Разработчик может забыть проверить пустую строку, и задача создастся с пустым названием, что потом затруднит идентификацию задач и нарушит целостность данных. Это опасно, потому что в списке появятся «безымянные» задачи, которые невозможно отличить друг от друга.
